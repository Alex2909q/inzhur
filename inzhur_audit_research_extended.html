Monobank: архітектура авторизації, сесій та операцій

Український мобільний необанк («Універсал Банк»). Пароля немає: вхід PIN-кодом або Face ID лише з одного прив'язаного смартфона

Слайд 2 з 13
Кейс №1: Monobank
1. Пароль та веб-вхід Пароля немає: замінений 4-значним PIN-кодом. Веб-кабінету для фізичних осіб немає (тільки мобільний застосунок). Для бізнесу та підприємців діє web.monobank.ua — вхід без пароля за QR-кодом або Push-підтвердженням у додатку.
2. Apple ID та Google Sign-In Вхід через Apple ID: підтримується на iPhone для швидкої авторизації та відновлення сесії (з прив'язкою до фінансового номера). Вхід через Google на Android відсутній.
3. Щоденний вхід (PIN / Face ID) Щоденний вхід: 4-значний PIN-код або системна біометрія (Face ID / Touch ID). Ліміт у 3–5 невдалих спроб блокує сесію до проходження відеоселфі-перевірки.
4. Підтвердження операцій Купівля та продаж: купівля державних облігацій здійснюється в 1 клік у межах активної сесії. Продаж цінних паперів і грошові перекази підтверджуються 4-значним PIN-кодом або Face ID / Touch ID у застосунку (без SMS-кодів).
5. Новий пристрій та сесії Один активний пристрій (Single Active Device): дозволений лише один активний смартфон (вхід на новому девайсі автоматично завершує попередню сесію). Авторизація: номер телефону + SMS-код (або Apple ID) + PIN-код або селфі-перевірка → підключення біометрії та лист-підтвердження на пошту.
6. Ключ входу (Passkey) Не використовується. Підтримки стандарту Passkeys у застосунку немає.
7. Зміна номера та PIN-коду Зміна номера: в активному додатку — за SMS-кодом на новий номер; при втраті старого номера — через відеоверифікацію зі службою підтримки або шеринг документів через Дію.
Зміна/відновлення PIN-коду: у налаштуваннях картки, або при втраті PIN-коду на вході — через автоматичну відеоселфі-перевірку (звірка з фото в базі) та встановлення нового PIN-коду.
Ключовий висновок для Inzhur: Monobank доводить, що 4-значний PIN-код є повністю надійним за суворої політики одного активного пристрою та відновлення доступу виключно через селфі-перевірку або Дію.

Privat24: архітектура авторизації, сесій та операцій

Слайд 3 з 13
Кейс №2: Privat24
1. Пароль та веб-вхід Сценарії використання: Текстовий пароль зберігається для первинного входу та веб-версії. Веб-вхід без пароля: на сайті діє динамічний QR-код, який сканується мобільним застосунком Privat24 для входу в 1 клік.
2. Apple ID та Google Sign-In Відсутній. Сторонні сервіси швидкого входу (Apple, Google) не використовуються — авторизація побудована суворо на фінансовому номері телефону та паролі.
3. Щоденний вхід (PIN / Face ID) Щоденний вхід: Face ID / Touch ID або пароль від акаунта. Окремого 4-значного PIN-коду додатка немає (PIN-код діє лише для банківських карток).
4. Підтвердження операцій Підтвердження операцій: операції з цінними паперами та платежі підтверджуються в мобільному застосунку через біометрію (Face ID / відбиток пальця) або пароль входу.
5. Новий пристрій та сесії Мультисесійність: дозволені паралельні активні сесії (веб-сайт та смартфони з контролем у меню безпеки). Вхід на новому пристрої: телефон + пароль → обов'язкове друге підтвердження (Push в авторизованому додатку, QR-код, дзвінок/SMS або PIN-код картки) → підключення біометрії.
6. Ключ входу (Passkey) Не використовується. Підтримки ключів входу Passkey немає.
7. Зміна номера та пароля Зміна номера: у додатку (SMS на старий номер + PIN-код картки), через банкомат/термінал із фізичною карткою або при втраті номера — через підтримку з верифікацією через Дію.
Зміна/відновлення пароля: номер телефону → SMS або дзвінок → введення 4-значного PIN-коду активної банківської картки.
Ключовий висновок для Inzhur: Еталонний кейс поєднання обов'язкового пароля для сайту, швидкого безпарольного входу через динамічний QR-код та підтвердження операцій усередині додатка без використання SMS.

Кейс №3: Revolut
1. Пароль та веб-вхід Сценарії використання: Класичного пароля немає — використовується 6-значний (або 4-значний) числовий Passcode. Веб-вхід (app.revolut.com): телефон/email + Passcode + Push у додатку, або без пароля через QR-код чи Passkey.
2. Apple ID та Google Sign-In Розділення особистого та бізнес-кабінету: у роздрібному додатку Revolut Personal прямого входу через кнопки Apple чи Google немає (вхід за номером телефону + Passcode або Passkey). У Revolut Business підтримується прямий вхід через Apple ID та Google.
3. Щоденний вхід (PIN / Face ID) Щоденний вхід: числовий Passcode або системна біометрія (Face ID / Touch ID). Заборонені прості комбінації, а після 3–5 невдалих спроб доступ блокується до проходження селфі-верифікації.
4. Підтвердження операцій Біометричний захист операцій: перекази та продаж активів підтверджуються Passcode або Face ID. Для виведення заощаджень і великих сум діє Wealth Protection — додаткова відеоселфі-перевірка обличчя, що захищає кошти навіть при крадіжці розблокованого смартфона.
5. Новий пристрій та сесії Строгий онбординг нового девайса: номер телефону → Passcode → SMS-код (або посилання на email) → обов'язкова відеоселфі-перевірка. Попередній пристрій отримує Push-сповіщення про новий вхід.
6. Ключ входу (Passkey) Повноцінно діє: підтримується для швидкого входу та підтвердження операцій на вебі й у додатку (через Apple iCloud Keychain або Google Password Manager).
7. Зміна номера та коду доступу (Passcode) Зміна номера: в авторизованому додатку — за SMS-кодом на новий номер та Passcode; при втраті старого номера — через email + Passcode + обов'язкову відеоселфі-перевірку (та фото документа за запитом).
Зміна/відновлення Passcode: у налаштуваннях безпеки за старим кодом, або при втраті на вході — через SMS/email + обов'язкову відеоселфі-перевірку.
Ключовий висновок для Inzhur: Революційний бенчмарк: замість надлишкових SMS-підтверджень операцій Revolut використовує локальний Face ID для щоденного входу та селективну селфі-перевірку (Wealth Protection) для захисту виведення коштів.

Кейс №4: Wise

2. Apple ID та Google Sign-In Повна інтеграція: реєстрація та вхід через Apple ID та Google працюють в 1 клік на веб-сайті та в мобільному застосунку.

6. Ключ входу (Passkey) Вхід та підтвердження за замовчуванням: Passkey працює як для безпарольного входу, так і як основний метод підтвердження операцій (синхронізується через iCloud, Google або 1Password).

Зміна/відновлення пароля: посилання на email + діючий метод другої перевірки (при втраті пошти — SMS на телефон + селфі з документом).

1. Забув пароль (на веб-сайті або новому телефоні) Відновлення виключно через посилання на електронну пошту. Через це Inzhur зараз жорстко зав'язаний на обов'язковий email на першому кроці онбордингу. Натиснути «Забули пароль?». Розгалуження за наявністю Email:
• Варіант А (Якщо є прив'язаний Email): ввести email → отримати одноразове посилання на пошту (діє 30–60 хвилин) → підтвердити дію SMS-кодом або Passkey → задати новий пароль.
• Варіант Б (Пропозиція без Email — за номером телефону): якщо email відсутній, система обов'язково запитує номер телефону → перевірка кодом із SMS → обов'язкове підтвердження через Дія.Підпис або BankID → встановлення нового пароля.
• Альтернатива для сайту: швидке скидання пароля через сканування QR-коду камерою мобільного додатку Inzhur із підтвердженням за Face ID або PIN-кодом на активному смартфоні.
Кошти захищені закритим контуром виплат (переказ суворо на підтверджений власний рахунок IBAN інвестора). 		До Варіанту А (посилання на пошту + друга перевірка):
• Wise: скидання пароля через одноразове посилання на email + SMS-код або Push-підтвердження у додатку.
• Kraken: лист на email + обов'язковий окремий головний ключ безпеки (Master Key / Passkey).
До Варіанту Б (без пошти — телефон + Дія / біометрія):
• Sense Bank: зміна фінансового номера та ідентифікація за номером телефону через документи у застосунку Дія та селфі-перевірку без електронної пошти.
• Monobank: повністю безпарольна модель (пароль відсутній як сутність, вхід за номером телефону та PIN-кодом або відеоселфі; відновлення доступу через Дію).
До альтернативи на сайті (через QR-код):
• Privat24, Binance, Bybit: миттєвий вхід на веб-сайт без введення пароля через сканування QR-коду мобільним додатком.
2. Забув PIN-код у мобільному застосунку Тільки через ручне звернення до клієнтської підтримки. Натиснути «Забули PIN-код?». Розгалуження сценаріїв відновлення:
• Варіант А (Якщо є прив'язаний Email): ввести email → одноразове посилання на пошту + код із SMS → задати новий PIN-код на сервері.
• Варіант Б (Пропозиція без Email — за номером телефону): якщо email відсутній, система обов'язково запитує номер телефону → код із SMS → введення чинного пароля від кабінету. Якщо пароль також забуто — автоматичний перехід у Дію (Дія.Підпис) або BankID для підтвердження особи інвестора → задати новий 4-значний PIN-код на сервері. (Швидка безпечна верифікація через Дію без очікування листів!). 		До Варіанту А (через пошту та повторну авторизацію):
• Wise: скидання коду доступу до додатка через повторну авторизацію (пароль або посилання на email + SMS-код).
До Варіанту Б (чинний пароль кабінету):
• Privat24: відновлення входу в мобільний додаток через номер телефону, SMS/дзвінок та чинний пароль акаунта.
До Варіанту Б (відновлення без пошти):
• Monobank: скидання забутого PIN-коду на екрані входу через відеоселфі-перевірку без пошти.
• Sense Bank: скидання PIN-коду за номером телефону, SMS та реквізитами картки або паспортними даними без пошти.
3. Змінив або втратив номер телефону Ручна верифікація через клієнтську підтримку. Суворо заборонити зміну номера лише через пошту (вразливість TransferGo)!
Цільовий шлях: ввести новий номер → код із SMS на новий номер → обов'язкова верифікація через Дія.Підпис або BankID (підтвердження особи інвестора).
Розгалуження сповіщень безпеки:
• Якщо є прив'язаний Email: контрольний лист про зміну номера.
• Якщо Email відсутній: негайне повідомлення SMS на фінансовий номер із посиланням на блокування в 1 клік + Push-сповіщення у попередній телефон. 		Захист від зміни номера лише за поштою (закриття вразливості):
• Monobank: при втраті старого номера заборонена зміна за email — обов'язкова відеоверифікація з підтримкою або шеринг документів через Дію.
• Sense Bank: зміна фінансового номера у застосунку підтверджується документами через Дію та селфі-перевіркою.
• Privat24: зміна фінансового номера суворо через банкомат або термінал із фізичною карткою та PIN-кодом.
4. Вхід з нового телефона Немає автоматичного виходу на попередньому пристрої та контрольного сповіщення. 1) Вхід: Номер телефону + код із SMS + пароль (або швидкий вхід через Apple ID / Google Sign-In із перевіркою SMS).
2) Попередній смартфон автоматично виходить із сесії (політика одного активного смартфона — як у Monobank).
3) Розгалуження сповіщення «Вхід з нового пристрою»:
• Якщо є Email: контрольний лист із кнопкою «Це не я — заблокувати акаунт» (модель Binance / Monobank).
• Якщо Email відсутній: негайне повідомлення SMS на фінансовий номер із посиланням на блокування в 1 клік + Push-сповіщення у додаток на попередній телефон.
4) Завдяки закритому контуру виплат на власний рахунок IBAN немає потреби блокувати клієнта на добу. 		До політики 1 активного смартфона:
• Monobank: дозволена сесія лише на одному смартфоні — вхід на новому пристрої миттєво розриває сесію на попередньому.
До сповіщення з блокуванням у 1 клік:
• Binance та Bybit: миттєвий лист про вхід із нового пристрою з кнопкою екстреного заморожування акаунта в 1 клік.
• WhiteBIT: миттєве сповіщення безпеки про новий девайс з IP-адресою та керуванням активними сесіями.
Головний висновок для бізнесу та команди: Завдяки виплатам суворо на власний рахунок інвестора через банківську систему (закритий контур IBAN) та можливості депозитарного скасування операцій протягом 24 годин, безпека коштів гарантована на банківському рівні. Це дозволяє впроваджувати швидкі сценарії відновлення доступу (зокрема без обов'язкового email — через Дія.Підпис або BankID) та зберігає зручність виплат без компромісів у безпеці.

Вхід через Apple ID та Google: як це працює простою мовою

Для користувача це одна кнопка («Продовжити з Apple / Google»), але під капотом сервер Inzhur розрізняє два чіткі сценарії: Реєстрація та Авторизація

Слайд 13 з 13
Сценарії роботи сервера
СЦЕНАРІЙ 1 РЕЄСТРАЦІЯ (Новий користувач)
Мета: Миттєво створити обліковий запис без вигадування пароля та очікування листа з кодом на пошту, а далі перевести людину на верифікацію.
1. Клік: Користувач відкриває Inzhur і тисне «Продовжити з Apple» (або Google).
2. Підтвердження на пристрої: Спрацьовує Face ID або вибір Google-акаунта (займає 2 секунди).
3. Робота сервера Inzhur (Перевірка та розгалуження):
  • Сервер отримує від Apple або Google унікальний ідентифікатор користувача, email (якщо надано) та ім'я.
  • Розгалуження за наявністю Email:
    • Якщо email передано: створює нову чернетку профілю й одразу ставить відмітку «Пошту підтверджено».
    • Якщо email відсутній або прихований («Hide My Email» в Apple ID): сервер обов'язково запитує номер телефону як первинний ідентифікатор інвестора.
4. Обов'язкові кроки (бо ми — фінансова компанія):
Оскільки Apple і Google не передають телефон та податковий номер, клієнт проходить обов'язкові кроки:
  • Крок А (Фінансовий номер): обов'язковий екран «Введіть номер телефону» (якщо немає email або на першому кроці) → перевірка кодом із SMS.
  • Крок Б (Захист додатка): «Придумайте 4-значний PIN-код» (криптографічна прив'язка до чіпа смартфона).
  • Крок В (Верифікація документів): Перехід у Дію або BankID для передачі документів та підписання анкети.
💡 Важливий нюанс (Об'єднання профілів та розгалуження):
• Якщо є Email: якщо клієнт раніше реєструвався за поштою ivan@gmail.com і паролем, а тепер тисне «Google» — сервер бачить знайомий email і автоматично об'єднує Google-акаунт зі старим профілем Івана без створення дублікатів.
• Якщо Email прихований або відсутній: система обов'язково запитує номер телефону → після SMS-перевірки та верифікації в Дії або BankID сервер прив'язує Apple/Google ID за номером телефону без дублювання.
СЦЕНАРІЙ 2 АВТОРИЗАЦІЯ (Повторний вхід)
Мета: Максимально швидко та безпечно пустити клієнта у його кабінет (новий iPhone, перевстановлення застосунку або веб-сайт).
Варіант А: Щоденний вхід у мобільний застосунок (сесія активна)
Користувачу не потрібно щоразу тиснути кнопку Apple чи Google. Він просто відкриває іконку Inzhur → Face ID або 4-значний PIN-код (серверна перевірка прив'язаного пристрою) → він у кабінеті.
Варіант Б: Вхід після перевстановлення або на новому телефоні
1. Клік «Увійти з Apple / Google» → сервер знаходить профіль за унікальним ідентифікатором.
2. Обов'язкова друга перевірка: сам по собі вхід через пошту на новому девайсі — це лише перший фактор. Оскільки новий телефон ще не прив'язаний до акаунта, сервер вимагає підтвердити вхід фінансовим номером (SMS або Дія) та задати PIN-код для цього пристрою.
Варіант В: Вхід у веб-кабінет з комп'ютера
На сайті клієнт тисне «Увійти з Google / Apple» (або сканує QR-код застосунком). Якщо на комп'ютері налаштований Passkey — миттєвий вхід за Touch ID або Windows Hello в 1 клік. Якщо Passkey немає — підтвердження через додаток (Push-сповіщенням або кодом) та банер: «Створіть Passkey для входу в 1 клік».
Коротке резюме для презентації та технічного завдання розробникам:
Етап Що замінює Apple / Google Що робить сервер Inzhur Що залишається пройти клієнту
Реєстрація (Sign Up) Введення Email, вигадування пароля, введення коду з листа для підтвердження пошти. Створює профіль, зберігає унікальний ідентифікатор. Якщо є email — пошта одразу підтверджена. Якщо email немає або приховано — обов'язково запитує номер телефону. Вказати телефон → Задати PIN-код → Пройти верифікацію через Дію або BankID.
Авторизація (Log In) Згадування логіна та введення пароля (повністю унеможливлює проблему забутого пароля). Знаходить профіль за ідентифікатором. Якщо не знайдено — об'єднує за email; якщо email відсутній — запитує телефон і об'єднує за номером через Дію або BankID. Знайомий пристрій: тільки PIN-код або Face ID.
Новий пристрій або веб-сайт: друга перевірка (QR-код, Push, SMS) або Passkey.
⚠️ Чому для фінансових сервісів (як Inzhur) Telegram — це ризик? Статус: Під питанням
На відміну від Apple ID та Google, Telegram в Україні є мішенню №1 для фішингу:
1. Масовий злам: Крадіжки через фішинг (голосування, петиції); без хмарного пароля акаунт перехоплюють за 30 секунд.
2. Прямий ризик: Отримавши месенджер, зловмисник може в 1 клік увійти до кабінету інвестора на сайті.
3. Рішення: Вхід через Telegram допустимий лише з обов'язковою другою перевіркою (PIN-код смартфона або Passkey).
